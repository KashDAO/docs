description: 'End to end on staging: create an account for a user, fund it, trade, receive webhooks and withdraw.'
---

This walks through one user's journey on staging, first with `curl` and then with `@kashdao/sdk`. You need a partner test key with a webhook URL, which ZeroID issues on request: see [Keys](/developer-docs/partner-integration/keys#ask-for-a-test-key).

```bash
export KASH_API=https://api-staging.kash.bot/v1
export KASH_PARTNER_KEY=kash_test_...   # from your secret store
```

## 1. Create the user's account

When a user of Harbour Sports Picks opts in, create their account with your own id for them, their own address in your app, their country and their consent:

```bash
curl -X POST "$KASH_API/partner/accounts" \
  -H "X-API-Key: $KASH_PARTNER_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: onboard-3f6b2a1c-9d4e-4c7a-8b5f-2e1d0c9a8b7f" \
  -d '{
    "externalId": "hsp-user-8841",
    "destination": { "network": "solana", "address": "8yYpcE7Jx9NmXNMGR6NGumBUu4UBpMTVQW44P9hwikyh" },
    "country": "GB",
    "consent": { "acceptedAt": "2026-11-06T10:15:00Z", "termsVersion": "kash-terms-of-use-2025-06" }
  }'
```

Use one `Idempotency-Key` per onboarding attempt, stored with that pending onboarding, and reuse it only on retries of this request: a key reused to create the account again after a release would return the released account (see [Idempotency](/developer-docs/partner-integration/idempotency#creating-an-account-twice)). The destination is the user's Solana wallet address, not a token account address.

The answer is `202` with `account.accountId` and `status: "provisioning"`. Keep the `accountId` with your user:

```bash
export ACCOUNT_ID=7a1c2e3d-4b5f-4a6e-8d7c-1b2a3c4d5e6f
```

## 2. Wait for `account.active`

Your webhook endpoint receives `account.active` with the account's Solana `depositAddress`. Or poll until `status` is `active`:

```bash
curl "$KASH_API/partner/accounts/$ACCOUNT_ID" -H "X-API-Key: $KASH_PARTNER_KEY"
```

## 3. Fund it and read the balance

Ask ZeroID to fund the account with staging test USDC, and send the `accountId` (or the `depositAddress`) and the amount. You cannot mint test USDC yourself; see [Sandbox](/developer-docs/partner-integration/sandbox#test-usdc). Once ZeroID confirms, read the balance:

```bash
curl "$KASH_API/balance" \
  -H "X-API-Key: $KASH_PARTNER_KEY" \
  -H "Kash-Account: $ACCOUNT_ID"
```

`balance.availableAtomic` is what the account can spend, in atomic USDC: `"25000000"` is 25 USDC.

## 4. Find a market and quote it

Markets and quotes act for no account, so send no `Kash-Account` header:

```bash
curl "$KASH_API/markets?status=ACTIVE&category=sports&limit=5" \
  -H "X-API-Key: $KASH_PARTNER_KEY"

export MARKET_ID=...   # a market with "tradeable": true

curl "$KASH_API/markets/$MARKET_ID/quote?outcomeIndex=0&action=buy&amount=10000000" \
  -H "X-API-Key: $KASH_PARTNER_KEY"
```

The quote `amount` is atomic USDC (`10000000` is 10 USDC); the trade below takes the same 10 USDC as the decimal `"10"`.

## 5. Trade

```bash
curl -X POST "$KASH_API/trades" \
  -H "X-API-Key: $KASH_PARTNER_KEY" \
  -H "Kash-Account: $ACCOUNT_ID" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: hsp-order-55120" \
  -d '{
    "marketId": "'"$MARKET_ID"'",
    "outcomeIndex": 0,
    "amount": "10",
    "side": "buy",
    "clientRequestId": "hsp-order-55120",
    "metadata": { "externalId": "hsp-user-8841", "orderId": "55120" }
  }'
```

`clientRequestId` is your own id for the order. It is what makes a retry of this command safe: a repeat with the same `clientRequestId` and body returns the trade already placed instead of placing another, at any age. The `Idempotency-Key` alone does not guarantee that (see [Idempotency](/developer-docs/partner-integration/idempotency#trades)).

The trade `amount` is decimal USDC (`"10"` is 10 USDC). The answer is `201` with the trade in `pending`, and your endpoint receives `trade.completed`, `trade.failed` or `trade.rejected` when it ends.

## 6. Withdraw

Quote first, then withdraw. `Idempotency-Key` is required:

```bash
curl "$KASH_API/partner/accounts/$ACCOUNT_ID/withdrawals/quote?amountAtomic=5000000" \
  -H "X-API-Key: $KASH_PARTNER_KEY"

curl -X POST "$KASH_API/partner/accounts/$ACCOUNT_ID/withdrawals" \
  -H "X-API-Key: $KASH_PARTNER_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: hsp-withdrawal-90311" \
  -d '{ "amountAtomic": "5000000" }'
```

The answer is `202` with the withdrawal in `pending`. You receive `withdrawal.submitted`, then `withdrawal.completed` when the USDC reaches the user's destination.

## The same with the SDK

This uses `@kashdao/sdk` 0.4.0 (see [SDK](/developer-docs/partner-integration/overview#sdk)). Pass the user's `accountId` as `account` on the calls made for them; the SDK sends it as the `Kash-Account` header. The `partnerAccounts` methods name the account in the path instead.

```ts
import { randomUUID } from 'node:crypto';
import { KashClient } from '@kashdao/sdk';

const kash = new KashClient({ apiKey: process.env.KASH_PARTNER_KEY! }); // a kash_test_ key goes to staging

// 1. Create the account when the user opts in. Use one key per onboarding
//    attempt: create it now, keep it with the pending onboarding and reuse it
//    only on retries of this create.
const onboardingKey = `onboard-${randomUUID()}`;
const { account } = await kash.partnerAccounts.create(
  {
    externalId: 'hsp-user-8841',
    destination: { network: 'solana', address: '8yYpcE7Jx9NmXNMGR6NGumBUu4UBpMTVQW44P9hwikyh' },
    country: 'GB',
    consent: { acceptedAt: new Date().toISOString(), termsVersion: 'kash-terms-of-use-2025-06' },
  },
  { idempotencyKey: onboardingKey },
);
const accountId = account.accountId;

// 2. Wait until it is active (or handle the account.active webhook).
const active = await kash.partnerAccounts.waitUntilActive(accountId);
console.log('fund', active.depositAddress);

// 3. Once funded, read what the account can spend (atomic USDC).
const { availableAtomic } = await kash.balance.get({ account: accountId });
if (BigInt(availableAtomic) < 10_000_000n) throw new Error('fund the account first');

// 4. Markets and quotes act for no account.
const page = await kash.markets.list({ status: 'ACTIVE', category: 'sports', limit: 20 });
const market = page.data.find((m) => m.tradeable);
if (!market) throw new Error('no tradeable market');
const quote = await kash.quotes.buy({ marketId: market.id, outcomeIndex: 0, amountUsdcAtomic: '10000000' });
console.log('10 USDC buys', quote.tokensOut, 'outcome tokens');

// 5. Trade for the account. The trade amount is decimal USDC. clientRequestId
//    is your order id: a retry with it, even after a restart, returns the
//    trade already placed.
const trade = await kash.trades.create(
  {
    marketId: market.id,
    outcomeIndex: 0,
    amount: '10',
    side: 'buy',
    clientRequestId: 'hsp-order-55120',
    metadata: { externalId: 'hsp-user-8841', orderId: '55120' },
  },
  { account: accountId },
);
console.log('trade', trade.id, trade.status); // the outcome arrives by webhook

// 6. Quote a withdrawal to the registered destination, then send it.
const withdrawalQuote = await kash.partnerAccounts.withdrawals.quote(accountId, { amountAtomic: '5000000' });
console.log('at least', withdrawalQuote.receiveAtomic, 'arrives');
const withdrawalKey = randomUUID(); // keep it with the request on your side, and reuse it on retry
const { withdrawal } = await kash.partnerAccounts.withdrawals.create(
  accountId,
  { amountAtomic: '5000000' },
  { idempotencyKey: withdrawalKey },
);
console.log('withdrawal', withdrawal.withdrawalId, withdrawal.status);
```

To receive and verify the webhooks, see the receiver on [Webhooks](/developer-docs/partner-integration/webhooks#with-the-sdk).
