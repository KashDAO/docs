`@kashdao/protocol-sdk` is the **direct-to-chain** TypeScript SDK for
Kash. Its `@kashdao/protocol-sdk/solana` entry point talks straight to
the Kash market program on Solana mainnet-beta: no Kash backend and no
REST API in the trade path, no Kash-held keys, no Kash-sponsored fees.

If you want a hosted, API-key-authed integration (the fastest path to a
first trade), use the [REST API](/developer-docs/rest-api/overview) and
[`@kashdao/sdk`](/developer-docs/rest-api/sdks/typescript) instead. This
SDK is for builders who run their own signing infrastructure: market
makers, trading bots, AI agents and on-chain UIs.

## Trust model

The package never holds keys, never sponsors fees and never contacts
Kash-hosted infrastructure. You bring the RPC endpoint (or a
`Connection`), the signer and the funded wallet. It builds
`TransactionInstruction`s for the market program, asks your signer to
sign, and sends through your RPC. Kash sees only what lands on chain.

## Install

```bash
npm install @kashdao/protocol-sdk @solana/web3.js @coral-xyz/anchor @solana/spl-token bn.js
```

The four Solana packages are peer dependencies, so the SDK uses the
versions already in your tree (`@solana/web3.js` ^1.98, `@coral-xyz/anchor`
^0.32.1, `@solana/spl-token` ^0.4.9, `bn.js` ^5.2.1). Requires Node.js 22
or later.

`mainnet-beta` is the default. `getSolanaDeployment(cluster)` returns the
addresses, and `createSolanaClient({ cluster: { programId, usdcMint } })`
targets an unlisted deployment such as a local validator.

## Client surface

`createSolanaClient({ connection })` (or `{ rpcUrl }`) returns a client
with four namespaces:

| Method                                                                                                                | What it does                                                                                     |
| --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `markets.get(ref)`                                                                                                    | Decoded market: status (`active` / `frozen` / `resolved` / `cancelled`), prices, probabilities  |
| `markets.quoteBuy` / `quoteSell` / `quoteRedeem`                                                                      | Exact quotes from the program's own integer curve                                                |
| `account.position` / `positions` / `usdcBalance`                                                                      | Position balances and the wallet's USDC balance                                                  |
| `protocol.config` / `template` / `templates`                                                                          | Program config and market templates                                   |
| `trades.buildBuy` / `buildSell` / `buildRedeem` / `buildRedeemCancelled` / `buildOpenPosition` / `buildClosePosition` | A plan: the instructions plus the bounds they encode                                             |
| `trades.simulate(plan, { payer })` / `trades.send(plan, { signer })`                                                  | Simulate unsigned, or sign, send and confirm                                                     |
| `trades.buy` / `sell` / `redeem` / `redeemCancelled` / `openPosition` / `closePosition`                               | Build and send in one call, with the signer as trader                                            |

The low-level instruction builders (`buyInstruction`, `sellInstruction`,
`redeemInstruction`, …) and PDA derivations (`kashMarketPdas`) are
exported too, for composing your own transactions.

## Key concepts

- **Market references.** A market is named by its numeric id (`12n`) or
  its market account address. The REST API's `contractAddress` for a
  Solana market is that account address, so you can pass it straight
  to `markets.get`.
- **Amounts.** USDC is an atomic `bigint` with 6 decimals
  (`1_000_000n` = 1 USDC). Outcome balances are a WAD `bigint` with 18
  decimals (`10n ** 18n` = 1 token).
- **Positions are not SPL tokens.** The program keeps each position as a
  balance in a position account (one per market, owner and outcome).
  `buildBuy` opens that account in the same transaction when it is
  missing, and `closePosition` reclaims its rent once it is empty.
- **Slippage is mandatory.** Every trade takes `maxSlippageBps` (a floor
  derived from a fresh quote) or an explicit floor
  (`minTokensOutWad` / `minAmountOutUsdc`).
- **Signers.** `keypairSigner(keypair)` for bots and scripts;
  `walletAdapterSigner(wallet)` for `@solana/wallet-adapter`, Phantom or
  any wallet exposing `publicKey` and `signTransaction`. Pass `feePayer`
  to sponsor fees and rent from a second signer.
