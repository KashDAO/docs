**HTTP status:** 400 · **Title:** "Amount too large"

## When it fires

`amount` on `POST /v1/trades` exceeds the platform-wide per-trade ceiling. This safety net is separate from your key's per-trade and daily spending limits and applies whatever your tier.

## Why it happens

Almost always a **units mistake**: an amount in atomic units, such as `1000000` (1 USDC in 6-decimal units) or `1000000000000000000` (1 in 18-decimal units), sent where the API expects a human-readable USDC value such as `"1"`.

## How to fix

- Send `amount` as a string holding the USDC value a person would type: `"100"`, `"0.50"`, `"2500"`. Up to 6 decimal places are allowed.
- If you hold an atomic USDC value, divide by 10^6 first.
- Your key's own per-trade limit is lower than this ceiling; see [`SPENDING_LIMIT_EXCEEDED`](/developer-docs/api-errors/SPENDING_LIMIT_EXCEEDED) for how to raise it.

## Related codes

- [`SPENDING_LIMIT_EXCEEDED`](/developer-docs/api-errors/SPENDING_LIMIT_EXCEEDED) — your key's per-trade limit, separate from the platform ceiling
- [`VALIDATION_FAILED`](/developer-docs/api-errors/VALIDATION_FAILED) — the amount is not a valid USDC decimal string
