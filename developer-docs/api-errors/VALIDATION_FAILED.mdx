**HTTP status:** 400 · **Title:** "Validation failed"

## When it fires

The request body, path or query parameters failed validation: a field is missing, has the wrong type, or is out of range.

## Why it happens

- A required field is missing or `null`.
- A field has the wrong type, for example `amount` sent as a number instead of a string. Amounts are strings so they keep full precision.
- A field violates a constraint (UUID format, enum value, length, or a USDC amount with more than 6 decimal places).

## How to fix

- The `detail` field names the first offending field and the constraint it broke.
- Check the request schema in the [Endpoint reference](/developer-docs/rest-api/endpoint-reference) or the OpenAPI document at `https://api.kash.bot/v1/openapi.json`.
- The TypeScript SDK validates some request bodies before sending and raises `KashValidationError` client-side; server-side validation failures surface as the same class.

## Example

```json
{
  "type": "https://docs.kash.bot/developer-docs/api-errors/VALIDATION_FAILED",
  "title": "Validation failed",
  "status": 400,
  "code": "VALIDATION_FAILED",
  "detail": "amount '1.1234567' is not a valid USDC decimal string with up to 6 fractional digits.",
  "instance": "/v1/trades",
  "requestId": "01HQGY8K2N3X4Z5C6D7E8F9G0H"
}
```
