**HTTP status:** 503 · **Title:** "Service unavailable" · **Retry-After:** computed per response

## When it fires

Trading through the API is temporarily unavailable. It is returned by `POST /v1/trades` and `POST /v1/trades/{id}/confirm`.

Read endpoints (markets, quotes, portfolio, trade lookup) stay available throughout. Only trade writes are blocked.

## How to fix

- Honour `Retry-After` and back off. Polling faster will not restore it sooner.
- Keep using the read endpoints, and show a "trading temporarily unavailable" message in your UI rather than failing silently.
- The TypeScript SDK raises this as `KashMaintenanceError`.

## Related codes

- [`ROUTE_DISABLED`](/developer-docs/api-errors/ROUTE_DISABLED) — a single endpoint disabled, rather than all trading
- [`TRADE_ADMISSION_BUSY`](/developer-docs/api-errors/TRADE_ADMISSION_BUSY) — trading is busy, not unavailable
- [`DEPENDENCY_UNAVAILABLE`](/developer-docs/api-errors/DEPENDENCY_UNAVAILABLE) — an unplanned dependency failure
