**HTTP status:** 401 · **Title:** "Authentication required"

## When it fires

The `X-API-Key` header is well formed, but it does not match any key Kash knows about.

## Why it happens

- The key was deleted (not just revoked; see [`API_KEY_REVOKED`](/developer-docs/api-errors/API_KEY_REVOKED) for that case).
- A character was changed in transit or storage, for example a copy-paste that altered the value but kept its length.
- Wrong environment: a `kash_test_…` key sent to production, or a `kash_live_…` key sent to staging. Each environment accepts only its own keys.

## How to fix

- Compare the value you are sending with the key prefix shown in the Kash app (Settings → API Keys).
- If the prefix matches nothing in your account, the key has been deleted or was never yours. Issue a new one.
- If the prefix matches and authentication still fails, contact Kash support with the prefix and the `requestId` from a recent failed call.

Repeated authentication failures from one source trigger a temporary lockout, answered with [`RATE_LIMIT_EXCEEDED`](/developer-docs/api-errors/RATE_LIMIT_EXCEEDED). Fix the key before retrying.

## Related codes

- [`API_KEY_MISSING`](/developer-docs/api-errors/API_KEY_MISSING), [`API_KEY_MALFORMED`](/developer-docs/api-errors/API_KEY_MALFORMED) — earlier failure points
- [`API_KEY_REVOKED`](/developer-docs/api-errors/API_KEY_REVOKED) — the key existed but was revoked
- [`API_KEY_EXPIRED`](/developer-docs/api-errors/API_KEY_EXPIRED) — the key existed but is past its expiry
