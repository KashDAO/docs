**HTTP status:** 503 · **Title:** "Service unavailable" · **Retry-After:** computed per response

## When it fires

A service the endpoint depends on (for example Kash's database or a blockchain RPC provider) could not be reached, and the endpoint cannot answer without it. Almost every endpoint can return it.

It is distinct from [`INTERNAL_ERROR`](/developer-docs/api-errors/INTERNAL_ERROR) ("something unexpected happened") and from [`ROUTE_DISABLED`](/developer-docs/api-errors/ROUTE_DISABLED) ("Kash disabled this on purpose").

## Why it happens

- A transient infrastructure blip (most common; clears in seconds).
- A sustained outage of a dependency that Kash is already working on.

## How to fix

- Honour `Retry-After` and back off with jitter. Most occurrences clear within one retry.
- The TypeScript SDK raises this as `KashServerError` and retries it automatically within its retry budget.
- Retry writes with the same `Idempotency-Key` so a retry cannot execute twice. See [Idempotency](/developer-docs/rest-api/idempotency).
- If retries keep failing for more than a few minutes, contact Kash support with a `requestId`.
