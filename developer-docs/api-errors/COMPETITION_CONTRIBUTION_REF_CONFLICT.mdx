**HTTP status:** 409 · **Title:** "Contribution reference already used for a different amount"

## When it fires

`POST /v1/competitions/{competitionId}/contribute` was called with an `externalRef` that this member has already used for this entry, but with a **different** `amountAtomic`.

## Why it happens

`externalRef` is your idempotency handle for a contribution, normally the on-chain transfer's identifier. Sending the same ref twice with the same amount is safe and expected: a retry after a dropped connection resends the same ref, and the second call is a no-op that returns the member's unchanged running total.

Sending the same ref with a *different* amount cannot be a replay of the first request, so one of the two is wrong. Crediting the new amount would double-count against a pot that must reconcile with escrow. Ignoring it would be worse: the response would say `200` and report a total that does not include the money you believe you just sent. Under pooled funding that total decides how a real prize is split.

So the API refuses, and the `detail` names both amounts (the one already recorded and the one requested), so you can tell which of your two requests stands.

## How to fix

- **If the first request was correct**, no action is needed: it is already recorded. Read the member's total from the contribute response or the entry, and continue.
- **If you meant to contribute an additional amount**, send it under a **new** `externalRef`. Contributions accumulate, so a second ref adds to the member's total.
- **If you reused a ref by mistake** (for example a hard-coded value in a retry loop), make `externalRef` unique per contribution. It only needs to be unique per member per entry, so two different members may use the same on-chain identifier.
