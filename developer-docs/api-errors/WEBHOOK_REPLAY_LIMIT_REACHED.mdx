**HTTP status:** 429 · **Title:** "Replay limit reached"

## When it fires

`POST /v1/webhooks/events/{eventId}/redeliver` was called for an event that has already been redelivered the maximum of **5 times**.

## Why it happens

- Your integration called the redeliver endpoint in a loop instead of fixing the underlying delivery problem.
- An automation redelivered without checking previous attempts.
- A genuine need to redeliver one event many times, which is unusual and usually points to an endpoint problem.

The cap stops a leaked key from using the redeliver endpoint to flood your own webhook endpoint.

## How to fix

- Stop redelivering this event. The cap is per event, so other events can still be redelivered.
- Fix the delivery failure first. Check delivery status with `GET /v1/webhooks/events`, or the `webhookDelivery` field on `GET /v1/trades/{id}`.
- If you legitimately need more redeliveries of one event (for example after a long endpoint outage), contact Kash support.

See [Webhooks](/developer-docs/rest-api/webhooks/overview).
