---
title: 'Pagination'
description: 'Cursor-based pagination on every list endpoint.'
---

List endpoints return one page at a time with an opaque cursor. There is no offset pagination: offsets skip and repeat rows under concurrent writes.

## Paginated endpoints

| Endpoint | Order | Default limit | Max limit |
| -------- | ----- | ------------- | --------- |
| `GET /v1/markets` | newest first | 20 | 100 |
| `GET /v1/markets/{id}/predictions` | newest first | 50 | 100 |
| `GET /v1/trades` | newest first | 20 | 100 |
| `GET /v1/webhooks/events` | newest first | 25 | 100 |

A `limit` outside the allowed range is refused with `400 VALIDATION_FAILED`; it is not clamped.

`GET /v1/portfolio/positions` is **not** paginated: it returns every active position in one `{ data, _meta }` response, optionally filtered with `?marketId=`.

## Wire shape

```json
{
  "data": [ ],
  "pagination": {
    "cursor": "k2:eyJsaXN0Ijoi…",
    "hasMore": true,
    "limit": 25
  },
  "_meta": { "requestId": "…", "timestamp": "…" }
}
```

| Field     | Use |
| --------- | --- |
| `data`    | The items on this page. |
| `cursor`  | Pass it back as `?cursor=` to get the next page. `null` on the last page. |
| `hasMore` | `true` if another page follows. |
| `limit`   | The page size applied. |

No total count is returned.

## Walking pages

```bash
# First page
curl "https://api.kash.bot/v1/trades?limit=50" -H "X-API-Key: $KASH_API_KEY"
# → "pagination": { "cursor": "k2:…", "hasMore": true, "limit": 50 }

# Next page: same filters, plus the cursor
curl "https://api.kash.bot/v1/trades?limit=50&cursor=k2:…" -H "X-API-Key: $KASH_API_KEY"
# → "pagination": { "cursor": null, "hasMore": false, "limit": 50 }
```

Stop when `hasMore` is `false`.

With the TypeScript SDK, a list call returns a page you can iterate across every page:

```ts
const page = await kash.trades.list({ limit: 25 });
for await (const trade of page) {
  console.log(trade.id, trade.status);
}
```

## Rules for cursors

- **Opaque.** Don't decode or build cursors; the format can change.
- **Per list.** A cursor only works on the list that issued it. Passing a cursor from another endpoint returns `400 VALIDATION_FAILED`.
- **Keep your filters.** A cursor marks a position, not your filters. Send the same filters (`status`, `marketId`, …) on every page of one walk; to change filters, start again from the first page.
- **Stable under inserts.** Cursors are anchored to the last row you saw, so rows created during a walk never shift it. You won't see an item twice. Items created after you started appear when you start a new walk from the first page.

## Filtering

```bash
# Trades in two states
curl "https://api.kash.bot/v1/trades?status=pending,executing" -H "X-API-Key: $KASH_API_KEY"

# Trades on one market
curl "https://api.kash.bot/v1/trades?marketId=11111111-1111-4111-8111-111111111111" -H "X-API-Key: $KASH_API_KEY"

# Recent buys of outcome 0
curl "https://api.kash.bot/v1/markets/$MARKET_ID/predictions?outcomeIndex=0&side=buy&limit=20" \
  -H "X-API-Key: $KASH_API_KEY" -H "X-Kash-Api-Version: 2026-08-19"
```

Each endpoint's filters are listed on its [reference page](/developer-docs/rest-api/endpoint-reference).
