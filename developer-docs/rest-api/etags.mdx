title: 'ETags & Caching'
description: 'Conditional requests with If-None-Match: skip re-downloading unchanged data.'
---

Successful `GET` responses carry an `ETag` header. Send it back as `If-None-Match` and, if nothing has changed, the API answers `304 Not Modified` with no body.

## How it works

1. Make the request and keep the `ETag`:

   ```bash
   curl -i https://api.kash.bot/v1/portfolio/positions -H "X-API-Key: $KASH_API_KEY"
   # HTTP/1.1 200 OK
   # ETag: W/"…"
   # Cache-Control: private, no-cache
   ```

2. Send it back on the next poll:

   ```bash
   curl -i https://api.kash.bot/v1/portfolio/positions \
     -H "X-API-Key: $KASH_API_KEY" \
     -H 'If-None-Match: W/"…"'
   # HTTP/1.1 304 Not Modified   (no body: reuse what you have)
   # or
   # HTTP/1.1 200 OK             (new body and a new ETag)
   ```

On `304`, keep using your previous body. On `200`, replace it and keep the new ETag. `If-None-Match` accepts a comma-separated list of tags or `*`, and compares weakly, so echo back exactly what you received.

## Two kinds of ETag

| Route | ETag | What a `304` saves |
| ----- | ---- | ------------------ |
| `GET /v1/portfolio/positions` | **Weak** (`W/"…"`), derived from a fingerprint of your positions. | The server checks the fingerprint and answers `304` before running the positions query. Cheap for both sides. |
| Every other `GET` | **Strong** (`"…"`), a hash of the response body ignoring the per-request `_meta.requestId` and `_meta.timestamp`. | The body on the wire. The server still builds the response to compute the hash. |

Error responses carry no ETag. `POST` routes don't use ETags; use [idempotency](/developer-docs/rest-api/idempotency) instead.

## Rate limits

A `304` still counts as one request against your [rate limit](/developer-docs/rest-api/rate-limits). Conditional requests save bandwidth and work, not quota. If you need to watch trades closely, [webhooks](/developer-docs/rest-api/webhooks/overview) cost no quota at all.

## Where ETags help most

| Endpoint | Pattern | Benefit |
| -------- | ------- | ------- |
| `GET /v1/portfolio/positions` | Poll your positions | High: positions change only when your trades settle. |
| `GET /v1/trades/{id}` | Wait for a trade to finish | High until the status changes. |
| `GET /v1/markets/{id}` | Watch one market | Medium: probabilities move with every trade. |
| `GET /v1/markets/{id}/quote` | Live pricing | Low. Use its `Cache-Control: public, max-age=10` instead. |
| `GET /v1/markets/{id}/predictions` | Recent trades | Low: the feed changes constantly. Use the cursor. |

The TypeScript SDK sends `If-None-Match` for you when polling positions.

## `Cache-Control`

- `GET /v1/portfolio/positions`: `private, no-cache` (cache it yourself, revalidate every time).
- `GET /v1/markets/{id}/quote`: `public, max-age=10`.
- `/v1/openapi.json` and `/v1/docs`: `public, max-age=60, stale-while-revalidate=300`.
- `/v1/health`, `/v1/ready` and the webhook-secret rotation response: `no-store`.
