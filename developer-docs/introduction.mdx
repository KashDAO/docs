Welcome to the Kash developer documentation. Build trading bots and agents, trade directly against the on-chain markets, embed markets in your website, and read real-time market data.

Kash markets live on an open, permissionless protocol on **Solana**, and every balance, trade and redemption is in **USDC**. Kash provides an interface on top of that protocol.

<Note>
**Kash is non-custodial on every surface.** Kash never holds custody of user funds: they sit in wallets the user owns and controls. The surfaces below differ in **who orchestrates execution**, not in who holds the funds.
</Note>

## Pick your surface

<CardGroup cols={2}>
  <Card title="REST API" icon="bolt" href="/developer-docs/rest-api/overview">
    Kash-orchestrated programmatic access at `api.kash.bot`. Place trades, manage portfolios and receive HMAC-signed webhooks with an API key. Trades execute from the user's own embedded wallet under the trading permission they granted, and Kash builds the transaction and pays the network fee. The right surface for bots, agents and market makers who want managed execution without running infrastructure.
  </Card>
  <Card title="Protocol SDK" icon="cube" href="/developer-docs/protocol-sdk/overview">
    Self-orchestrated access. Bring your own signer and RPC, and transactions never touch Kash servers. TypeScript and Python implementations, with cross-language parity.
  </Card>
  <Card title="CLI" icon="terminal" href="/developer-docs/cli/overview">
    `kash`: the REST API packaged as a scripting-friendly command-line client. Ideal for one-offs, CI jobs, shell scripts and agent integrations.
  </Card>
  <Card title="Public Embed API" icon="window" href="/developer-docs/public-embed-api/overview">
    Read-only public surface at `app.kash.bot/api`. Drop iframes and market data into websites and articles. No authentication required.
  </Card>
</CardGroup>

<Note>
**Which one do I want?**
- Want Kash to build, submit and pay for transactions from a user's own embedded wallet? → **REST API**.
- Want to sign and submit transactions entirely with your own infrastructure? → **Protocol SDK**.
- Want to script flows from a terminal or CI? → **CLI**.
- Embedding markets in a website for people to view? → **Public Embed API**.
</Note>

## What can you build?

### Trading bots and agents
Use the [REST API](/developer-docs/rest-api/overview) to place trades, monitor portfolios and react to market events through webhooks. It supports idempotent retries, per-key spending limits and per-key rate limiting. Users create keys in **Settings → API keys** on [app.kash.bot](https://app.kash.bot).

### Self-orchestrated trading and market making
Use the [Protocol SDK](/developer-docs/protocol-sdk/overview) (TypeScript or [Python](/developer-docs/protocol-sdk-python/overview)) to quote, sign and submit transactions yourself against the on-chain markets, with your own signer and RPC.

### Scripting and ops
Use the [CLI](/developer-docs/cli/overview) for shell-driven workflows: list markets, get quotes, place trades, manage webhooks and decode error codes, all with a stable JSON envelope for piping into `jq` or agent contexts.

### Embedded prediction markets
Use the [Public Embed API](/developer-docs/public-embed-api/overview) to put live, read-only markets into news sites, financial platforms or community forums. Visitors go to app.kash.bot to trade.
