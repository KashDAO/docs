Kash has two APIs you can build on: the authenticated **REST API** at `api.kash.bot/v1` for reading markets and trading programmatically, and the **Public Embed API** for showing markets on your site with no key at all.

## REST API keys

Keys for the REST API are created in the Kash web app under **Settings → API Keys**. Each key belongs to an organization, and if that organization is suspended its keys stop working.

- **Scopes:** each key carries explicit scopes, so a reporting integration can have read-only access while trading lives on a separate key.
- **Tiers:** each key's tier sets its rate limit and spending caps. `free` is self-serve; `developer`, `enterprise` and the market-maker tier `mm` are issued by Kash.
- **IP allowlists and webhooks:** lock a key to your servers, and receive signed webhooks instead of polling.

## No key needed: the Public Embed API

If you only need to display markets, the [Public Embed API](/developer-docs/public-embed-api/overview) is public, read-only and needs no key. It includes drop-in widgets for a single market, a thread of markets, or every market your organization runs.

## Embeds and revenue share

Embedding helps people find your markets, but revenue share follows who **created** a market, not where a trade happens. A trade in your market counts whether it comes from app.kash.bot, an embed on any site, or X. Embedding someone else's market doesn't earn you its revenue share.
